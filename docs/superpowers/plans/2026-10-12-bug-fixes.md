# Bug-Audit Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix every scheduled defect in `docs/BUG_AUDIT_2026-10-12.md` so that cleaned outputs are valid, nothing that should be removed leaks, and every advertised feature works on Android and iOS.

**Architecture:** Each task fixes one subsystem with test-first changes that stay inside the existing Clean Architecture layers:
- format registry (`lib/core/format`)
- byte strippers (`features/remover/data/datasources/strippers`)
- ZIP helpers (`lib/core/processing`)
- viewer extractors
- `RemoverBloc`
- settings and onboarding UI

Two new shared helpers are introduced: `ogg_crc.dart` and `pdf_info_locator.dart`.

**Tech Stack:** Flutter/Dart, flutter_bloc + bloc_test, `archive` 3.6.x, `xml`, `saf`, `file_selector`.

**Spec:** `docs/BUG_AUDIT_2026-10-12.md` (finding IDs C*/H*/M*/L*). Read the matching row before starting each task.

## Decisions required before execution

Tasks marked **(D#)** wait on these. Each has a recommendation; if it is approved, implement it as written.

- **D1 — Firebase Analytics (C4).** Recommendation: remove it completely, to match `PRIVACY-POLICY.md` and the offline promise. The alternative is to keep it and rewrite the privacy policy and Play data-safety form, which this plan does not cover.
- **D2 — CI toolchain (H10).** Recommendation: pin CI to the dev-box Flutter version, **3.41.7**, and raise the pubspec constraint to `flutter: '>=3.35.0'`. The alternative is rewriting `RadioGroup`, `withValues` and `toARGB32` usages for 3.22.
- **D3 — iOS output folder (C5).** Recommendation: on iOS, skip the folder picker and use `getApplicationDocumentsDirectory()/MetaStrip`. Files then become visible in the Files app through `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`. A security-scoped bookmark picker would need a new plugin and is out of scope.
- **D4 — JPEG APP2 / ICC (M3/M4).** Recommendation: keep `ICC_PROFILE` APP2 segments for colour fidelity, and drop the other APP2 payloads (FlashPix and MPF).
- **D5 — Unused output settings (L5).** Recommendation: label `namingTemplate` and `folderStructure` "Not yet applied" and disable them, as the Processing section already does. Wiring them into the remover is new work, not a fix.

## Global Constraints

- **Toolchain:** after Task 1, CI and code target Flutter 3.41.7 / Dart 3.11.x with pubspec `flutter: '>=3.35.0'` (D2). Until Task 1 lands, use no new APIs at all.
- **Offline-only:** add no network code or SDKs. The merged release manifest must not request `android.permission.INTERNET`.
- **Originals:** never mutate an original. Clean copies use `<name>_clean[_N].<ext>`. Existing claim/tmp semantics are unchanged.
- **Failure messages:** malformed or unsupported input fails closed with `FormatException`, never a `RangeError`, and never a "successful" unchanged copy.
- **Dependencies:** no `get_it`, `go_router` or `bloc_concurrency` unless separately approved.
- **Done means:** `flutter analyze` reports "No issues found!" and `flutter test` reports "All tests passed!" after each task.
- **Git hygiene:** the worktree contains user-owned uncommitted work, including the PDF XMP files, `pdf_info_validator.dart`, `remover_screen_test.dart` and the deleted `*.out.txt` logs. Stage only the files each task names.
- **Tests:** single file `flutter test <path>`; single case `flutter test <path> --plain-name "<name>"`.

## Review Focus

The audit implies these failure modes, but no unit test below fully pins them. Each one has a test or manual check added to the owning task.

1. **Files produced by real third-party tools** (libogg, Photoshop CMYK JPEG, Word .docx, LibreOffice .odt with a chart) must still open in their native apps after cleanup. The tasks add independent reference implementations and a manual decoder check (Tasks 4, 7, 11, 12).
2. **A file exactly at a size limit** (50 MiB remover cap, 1 MiB MP3 prefix) is accepted, and limit + 1 is rejected (Tasks 5, 14).
3. **Second batch while one is running, or Clear/Back mid-batch:** no duplicate outputs and no resurrected state (Task 6).
4. **SAF `content://` output folders:** the folder can be re-picked from Settings and the export target works, with no `File` APIs used on a URI (Task 17).
5. **Truncated input after each parser change:** it fails closed with `FormatException` (Tasks 3, 4, 13–15).
